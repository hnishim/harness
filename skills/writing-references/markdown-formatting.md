# Markdown表示規範

**適用範囲**：MarkdownファイルまたはMarkdownとしてレンダリングされる文章の表示構造。本文の語句、文法、主張、論理、事実関係は扱わない。Markdown方言、既存形式、ツール固有の拡張が指定されている場合は、それらを優先する。

## ブロックの区切り

- 見出しは文書の先頭または末尾を除き、前後を空行1行で区切る。
- 段落、箇条書き、引用、フェンスドコードブロック、表などのブロック要素は、前後を空行1行で区切る。
- 同一階層の単純な箇条書きの項目間には空行を入れない。複数段落または入れ子を含む項目では、必要なインデントを保持する。
- 段落の区切り以外に不要な空行を連続させない。一文一行への機械的な分割もしない。

## 見出し、リスト、コード

- 新たに作る見出しはATX形式（`#`）を用い、`#` の後に半角スペースを1つ置く。既存の見出し形式は保持する。
- 見出しの階層を示すためだけに番号を付けない。番号が参照、手順、法令などの識別子として必要な場合、または既存文書・依頼で指定された場合だけ保持または付与する。
- 手順、順序、優先度を示す場合は番号付きリスト、並列項目には箇条書きを用いる。既存のリスト記号、階層、番号体系は保持する。
- 箇条書きの項目末尾は句点なしを基本とし、完全な文や既存の文書スタイルでは項目全体で統一する
- コードブロックはフェンスドコードブロックで区切り、言語を確実に特定できる場合だけ言語名を付ける。コードブロック内、インラインコード、リンク、表、引用、HTML、数式、コメントの内容は変更しない。
- ファイル名、パス、コマンド、識別子などを本文で示すときは、インラインコードで囲む。拡張子や大文字小文字を含む正式な表記はコード内容として保持する。例： `.textlintrc.json`。
- 文頭に置く場合も、コードスパン内の変数名、ファイル名、コマンド、識別子などの大文字小文字を文章規則で変更しない。
- 日本語の地の文にインラインコードを挿入するときは、コードスパンの外側に半角スペースを1つ置く。コード内容にはスペースを加えない。文頭・文末や句読点・括弧との接続では、Markdown構文と意味を壊さない範囲で調整する。
- 日本語の地の文にMarkdownリンクを挿入するときは、リンクスパンの外側に半角スペースを1つ置く。リンクラベルとリンク先URLの内部にはスペースを加えない。文頭・文末や句読点・括弧との接続では、Markdown構文と意味を壊さない範囲で調整する。
- 改行末の2個以上の半角スペースによる強制改行は、意図が明らかな場合だけ保持する。表示のために新しく加えない。

## 完了条件

- CommonMarkまたは指定されたMarkdown方言で、見出し、段落、リスト、コードブロックの境界が曖昧でない。
- 既存のMarkdown方言、拡張記法、保護構造を壊していない。
