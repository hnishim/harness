# Spike Mode

タイトルが `Spike:` で始まる、またはラベルに `Spike` が含まれるIssueでだけ読みます。

- タイトルとラベルが矛盾する場合は、タイトルとDescriptionの目的を優先し、判定理由をPlanに記載します。
- 通常modeではIssueにない仕様を確定しません。Spike modeでは、検証に必要な局所的で可逆的な細部だけ暫定判断を置けます。
- 暫定判断には `暫定判断`、根拠、影響範囲、検証方法、変更可能性を記録します。ホットキー、検証用モデル、ファイル配置、最小UI、検証用エラー表示などが対象です。
- `PLAN_BLOCKED` にするのは、外部APIへの実データ送信、本番データ、認証情報、課金、権限、セキュリティ、不可逆な変更など、暫定判断でも安全に検証できない事項に限ります。
- 受入条件は完成品の品質ではなく、各検証点の成功・失敗・未検証を判定でき、暫定判断、技術的制約、未実装範囲、次の判断事項を記録できることです。
